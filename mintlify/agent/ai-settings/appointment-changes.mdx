Le code comprend des parcours d’identification, d’annulation et de déplacement. Ils doivent être activés et qualifiés dans votre espace avant usage client.

Un test réussi de création Google ne prouve pas qu’un déplacement ou une annulation a été testé de bout en bout.

## Préparer les règles

Dans **Agent > Paramètres IA**, recherchez les changements de rendez-vous. Choisissez les actions autorisées et le niveau de vérification proposé.

L’identification peut s’appuyer sur le téléphone, le nom et des détails du rendez-vous. Une confirmation explicite doit précéder l’action. Si l’identité ou le rendez-vous reste ambigu, faites prendre un message à votre équipe.

## Attention au code à usage unique

Un mode de vérification par code nécessite un moyen d’envoi fonctionnel. Le numéro pilote Voice-only ne peut pas envoyer de SMS.

N’activez pas une politique qui impose un code SMS sans avoir validé un expéditeur compatible et le parcours de réception. Ne contournez pas une vérification en affaiblissant les règles pour un client sensible.

## Test de qualification

1. Créez un rendez-vous fictif dans un agenda de test.
2. Vérifiez que l’appelant ne peut modifier que le rendez-vous attendu.
3. Demandez une modification, puis confirmez-la explicitement.
4. Relisez le nouveau statut et l’horaire dans l’application.
5. Relisez l’événement chez Google.
6. Contrôlez les refus : identité ambiguë, action désactivée et créneau indisponible.

Ne répétez pas une action après une erreur réseau sans vérifier son résultat : vous pourriez créer une situation incohérente.

## Notifications et reprise humaine

Une modification peut réussir sans SMS ou email. L’état d’envoi doit être contrôlé séparément.

En cas d’échec, relevez l’identifiant du rendez-vous et de l’appel. Confiez la correction à votre équipe ; ne promettez pas un transfert humain non qualifié.

## Actions et confirmation attendues

Le parcours peut retrouver un rendez-vous à venir, demander confirmation, annuler ou proposer un autre créneau lorsque l'action est autorisée. Une demande vague ne doit pas provoquer de changement : faites confirmer service, date, heure locale et action exacte.

La politique peut utiliser téléphone, nom et détail du rendez-vous. Ces éléments ne constituent pas une garantie universelle d'identité. En cas d'ambiguïté, recueillez une demande de suivi pour l'équipe.

## Activer les contrôles séparément

1. Ouvrez Agent > Paramètres IA pour la bonne entreprise.
2. Recherchez les changements de rendez-vous.
3. Réglez séparément annulation et déplacement.
4. Choisissez la vérification après avoir validé son moyen de livraison.
5. Enregistrez et vérifiez les valeurs après rechargement.

Pour une annulation, relisez le statut et l'effet exact sur l'événement Google. Pour un déplacement, contrôlez le nouveau créneau, la durée et l'agenda. Vérifiez aussi code faux ou expiré lorsque cette politique s'applique. Conservez les services et les droits calendrier à jour.
