Un client doit prendre en charge le transport Streamable HTTP et le mécanisme d’accès retenu. Aucun client externe n’est déclaré compatible sans test.

## Paramètres

| Élément | Valeur |
| --- | --- |
| Serveur SaaS | `https://receptionist.caleonis.com/api/mcp` |
| Transport | Streamable HTTP |
| Clé API | En-tête `Authorization: Bearer <clé>` |
| OAuth | Seulement si le parcours proposé est disponible et qualifié |

Sur une installation auto-hébergée, remplacez le domaine par celui de votre installation. Ne recopiez pas les secrets du SaaS.

## Séquence de qualification

1. Utilisez une entreprise de test autorisée.
2. Accordez une permission minimale en lecture.
3. Vérifiez le nom de l’entreprise et une lecture simple.
4. Vérifiez qu’une permission absente est refusée.
5. Vérifiez la gestion des limites et erreurs.
6. Révoquez l’accès puis contrôlez le refus.

Un succès HTTP ne prouve pas qu’un rendez-vous externe est synchronisé ni qu’une notification a été livrée.

## Écritures

Ajoutez progressivement les seules permissions nécessaires. Confirmez les effets de chaque action, utilisez l’idempotence disponible et ne traitez pas une demande d’outil comme une autorisation générale.

Voir [MCP](/ai/mcp) et [Requêtes et erreurs](/api/requests).
