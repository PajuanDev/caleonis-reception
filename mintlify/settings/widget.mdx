<Note>
Le widget existe dans le code du produit, mais les nouvelles clés sont désactivées par défaut. L’accès n’est pas une fonction publique incluse automatiquement dans une offre Caléonis V1.
</Note>

Les clés existantes autorisées peuvent conserver leur configuration. La voix dans le navigateur de test et le widget installé sur un site sont deux parcours distincts.

## Avant une installation

Faites confirmer l’activation dans votre entreprise. Préparez un site de test HTTPS que vous contrôlez et les origines exactes autorisées.

Ne copiez pas une clé d’une autre entreprise. Une clé de widget n’est pas une clé d’API administrative.

## Configurer une clé existante

Dans **Réglages > Widget**, si la page est disponible :

1. Choisissez la clé de votre site.
2. Vérifiez la couleur, la position, le titre, l’accueil et la langue.
3. Définissez les origines exactes autorisées.
4. Vérifiez les champs de contact demandés.
5. Copiez le code d’intégration fourni à l’écran dans votre site de test.

Évitez de collecter des informations inutiles. Ne demandez pas de données de santé dans le pilote.

## Vérifier le parcours

Ouvrez le site comme visiteur. Vérifiez l’affichage sur ordinateur et mobile, le formulaire, une réponse de chat et l’apparition du fil dans **Messages**, si le chat est activé.

Pour un appel Web autorisé, accordez le microphone et contrôlez ensuite la fiche dans **Appels**. Le test doit aussi échouer proprement sur une origine non autorisée.

## Suspendre

Utilisez les actions proposées pour suspendre ou révoquer une clé. La révocation interrompt les sites qui l’utilisent ; préparez cette action avec leur responsable.

La section [auto-hébergement](/self-hosting/overview) documente le contrôle technique d’émission des clés. Elle ne constitue pas une procédure d’activation du SaaS.
