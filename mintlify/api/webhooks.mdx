## Événements présents

| Type | Objet |
| --- | --- |
| `call.completed` | Appel terminé et résultat enregistré. |
| `appointment.booked` | Rendez-vous créé. |
| `appointment.rescheduled` | Rendez-vous déplacé. |
| `appointment.cancelled` | Rendez-vous annulé. |
| `message.taken` | Message de suivi pris pour l’équipe. |
| `contact.created` | Contact créé. |

L’enveloppe comprend `id`, `type`, `api_version`, `created_at`, `business_id` et `data`. Le contenu reflète l’état au moment de l’événement. Relisez la ressource API si vous avez besoin de son état actuel.

## Signature

Le code utilise le format Standard Webhooks :

| En-tête | Signification |
| --- | --- |
| `webhook-id` | Identifiant stable de l’événement. |
| `webhook-timestamp` | Heure de signature de la tentative. |
| `webhook-signature` | Signature versionnée. |

Vérifiez la signature sur le **corps brut**, avant de parser le JSON. La valeur signée associe l’identifiant, l’horodatage et ce corps, séparés par des points.

Le secret commence par `whsec_`. Utilisez une bibliothèque compatible et un contrôle d’ancienneté ; ne réimplémentez pas la comparaison cryptographique sans nécessité.

```ts
import { Webhook } from "standardwebhooks";

const verifier = new Webhook(process.env.CALEONIS_WEBHOOK_SECRET!);

export async function POST(request: Request) {
  const body = await request.text();
  const event = verifier.verify(body, Object.fromEntries(request.headers));
  // Dédupliquer event.id avant tout effet métier.
  // Traiter ou mettre en file durablement avant de confirmer.
  return new Response(null, { status: 204 });
}
```

Cet extrait illustre la vérification. Ajoutez la déduplication durable, la validation du type et le traitement métier de votre service avant usage réel.

## Réponse et reprises

Répondez rapidement avec un statut `2xx` après prise en charge durable. Le code prévoit un délai de réponse de 10 secondes et plusieurs reprises espacées en cas d’échec.

Un même événement peut arriver plusieurs fois ou dans un ordre différent. Dédupliquez sur son identifiant et relisez l’état métier si l’ordre importe.

Ne promettez pas une alerte email ou SMS automatique en cas d’échec : elle dépend de la configuration et de sa livraison réelle.

## Journal et rotation

Le journal montre les tentatives et réponses. Un renvoi manuel peut provoquer un nouvel effet si votre destinataire ne déduplique pas.

La rotation de secret exige une mise à jour coordonnée du destinataire. Ne faites pas cette opération sur un client actif pour un simple test.

Les destinations doivent être HTTPS et publiques. Les adresses privées, locales ou de métadonnées sont refusées par les protections réseau.
