---
title: "Authentifier les requêtes API"
description: "Créer des clés par entreprise et limiter les permissions des intégrations."
---
Les propriétaires et administrateurs peuvent gérer les clés depuis **Réglages > Clés d’API** si cette page leur est ouverte.

## Créer une clé

1. Vérifiez l’entreprise active.
2. Donnez un nom reconnaissable à l’intégration.
3. Choisissez uniquement les permissions nécessaires.
4. Copiez la clé lorsqu’elle est affichée.
5. Placez-la dans le gestionnaire de secrets du serveur destinataire.

Les clés conservent le préfixe technique `lsk_`. Ne le renommez pas pour le rebranding. La clé complète n’est pas destinée à être affichée à nouveau.

## Appeler une route

L’exemple utilise une variable locale choisie pour votre intégration ; il ne s’agit pas d’une variable interne à renommer dans l’application.

```bash
curl https://receptionist.caleonis.com/api/v1/me \
  -H "Authorization: Bearer $CALEONIS_API_KEY"
```

Vérifiez que la réponse concerne l’entreprise attendue. Une clé absente, inconnue ou révoquée doit être refusée.

## Permissions

| Permission | Accès |
| --- | --- |
| `business:read` | Entreprise, services et intervenants. |
| `business:write` | Modification de l’entreprise. |
| `calls:read` | Liste et détail des appels. |
| `contacts:read`, `contacts:write` | Lecture ou modification des contacts. |
| `appointments:read` | Rendez-vous et disponibilités. |
| `appointments:write` | Création, annulation et déplacement. |
| `messages:read` | Messages de suivi pris pour l’équipe. |
| `knowledge:write` | Ajout de connaissances. |
| `webhooks:manage` | Gestion et test des destinations webhook. |

`GET /me` sert au contrôle de toute clé valide. Une route sans permission suffisante répond `403` ; ne remplacez pas une clé limitée par une clé générale pour contourner ce résultat.

## Limites et révocation

La limite du code est de 120 requêtes par minute par défaut ; elle peut varier avec la configuration. Lisez les en-têtes de limite et respectez `Retry-After`.

Révoquez une clé qui n’est plus nécessaire ou a été exposée, puis remplacez-la dans les services autorisés. Vérifiez ensuite que l’ancienne clé est refusée.

Ne placez jamais une clé dans un widget, une application mobile publique, une capture d’écran ou une URL. La validation d’isolation doit inclure le refus d’une ressource appartenant à une autre entreprise.
