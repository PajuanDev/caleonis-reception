## Pagination

Les listes paginées retournent `data`, `next_cursor` et `has_more`. Renvoyez les mêmes filtres avec le curseur reçu pour charger la suite.

Le paramètre `limit` est borné par l’API. Les services, intervenants, disponibilités et destinations webhook peuvent utiliser une liste non paginée.

Traitez les curseurs comme opaques. Les dates doivent inclure un fuseau ou un décalage explicite ; encodez le signe `+` d’un paramètre URL.

## Répéter une création sans doublon

Les créations de contacts, rendez-vous, connaissances et webhooks prennent en charge `Idempotency-Key`.

```http
POST /api/v1/contacts
Authorization: Bearer <clé conservée côté serveur>
Content-Type: application/json
Idempotency-Key: <identifiant unique de votre opération>
```

Réessayez avec la **même clé et le même contenu** après une interruption dont le résultat est inconnu. Une même clé avec un contenu différent est rejetée.

La rétention d’idempotence du code est de 24 heures. Les opérations MCP correspondantes partagent ce mécanisme. Vérifiez toujours l’état métier après une erreur ambiguë.

## Erreurs usuelles

| HTTP | Code | Action |
| --- | --- | --- |
| 400 | `invalid_request` | Corriger le corps, les paramètres ou l’identifiant. |
| 401 | `unauthorized` | Vérifier la clé ou sa révocation. |
| 403 | `insufficient_scope` | Accorder seulement la permission nécessaire après validation. |
| 404 | `not_found` | Vérifier l’entreprise et l’identifiant, sans chercher à contourner l’isolation. |
| 409 | `booking_disabled` | La réservation est désactivée. |
| 409 | `booking_requires_confirmation` | La demande doit être confirmée par l’équipe. |
| 409 | `slot_unavailable` | Rechercher une autre disponibilité. |
| 409 | `idempotency_request_in_progress` | Attendre avant la reprise de la même opération. |
| 422 | `idempotency_key_reused` | Utiliser la bonne clé pour le contenu initial. |
| 429 | `rate_limited` | Attendre la durée de `Retry-After`. |
| 503 | `rate_limit_unavailable` | Réessayer plus tard sans désactiver les protections. |
| 500 | `internal_error` | Conserver la référence de l’erreur pour le support. |

Basez la logique sur `error.code`, pas sur la formulation de `error.message`.

## Réservation

La création et le déplacement doivent respecter le mode `instant`, les horaires, les fermetures, les disponibilités et la synchronisation calendrier.

Une clé d’entreprise agit pour l’entreprise ; elle ne remplace pas le parcours de vérification d’identité d’un appelant. Gardez les permissions d’écriture limitées.

Ne déduisez aucune notification du succès d’une réservation. SMS, email et Google ont chacun leur état. Le numéro pilote Voice-only ne permet pas de confirmation SMS.

## Intervenants

`GET /staff` décrit les intervenants réservables du modèle existant. Ce modèle technique n’est pas un système multi-agents. Utilisez les identifiants retournés plutôt que des valeurs inventées.
