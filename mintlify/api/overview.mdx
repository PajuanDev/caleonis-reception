La base de l’API du SaaS est `https://receptionist.caleonis.com/api/v1`. Le code expose des ressources pour l’entreprise associée à la clé.

Cette documentation décrit les routes présentes. L’accès, les droits et le parcours complet doivent être vérifiés dans votre environnement avant une intégration client.

## Ressources

| Ressource | Routes principales |
| --- | --- |
| Connexion | `GET /me` |
| Entreprise | `GET /business`, `PATCH /business` |
| Services et intervenants | `GET /services`, `GET /staff` |
| Appels | `GET /calls`, `GET /calls/{call_id}` |
| Contacts | `GET /contacts`, `POST /contacts`, lecture et modification par identifiant |
| Rendez-vous | Liste, lecture, création, annulation et déplacement |
| Disponibilités | `GET /availability` |
| Messages pris pour l’équipe | `GET /messages` |
| Connaissances | `POST /knowledge` |
| Webhooks | Liste, création, modification, suppression et test |

La ressource API **messages** correspond aux messages de suivi pris pour l’équipe. Ne la confondez pas avec une promesse d’envoi SMS ni avec toutes les conversations de la page **Messages**.

## Premier contrôle sans écriture

Créez une clé de lecture limitée, puis interrogez `GET /me`. Vérifiez l’entreprise retournée. Utilisez ensuite une route autorisée en lecture.

Ne créez pas de rendez-vous, de contact ou de webhook sur un espace client simplement pour tester la connexion.

## Référence

Consultez [Authentification](/api/authentication), [Requêtes et erreurs](/api/requests) et [Webhooks](/api/webhooks). La référence OpenAPI conserve les identifiants et certains libellés techniques en anglais.

Le [MCP](/ai/mcp) expose des actions existantes aux clients compatibles. Il s’agit d’une intégration développeur, sans nouveau système multi-agents métier en V1.
