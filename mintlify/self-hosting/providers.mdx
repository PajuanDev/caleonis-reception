La base Docker Compose exécute l'application Caléonis Receptionist, PostgreSQL, Redis et un volume de stockage local partagé. Connectez vos propres comptes fournisseurs pour les fonctionnalités externes.

## Requis pour les appels en direct

<AccordionGroup>
  <Accordion title="Twilio" icon="phone">
    Twilio fournit les numéros de téléphone, les transferts d'appel et la vérification des numéros de téléphone. Un trunk Elastic SIP envoie à OpenAI les appels reçus sur vos numéros. Chaque numéro doit faire partie du trunk pour répondre aux appels. Gardez le jeton d'authentification Twilio côté serveur.
  </Accordion>
  <Accordion title="OpenAI" icon="waveform">
    Le modèle GPT-Live d'OpenAI mène la conversation pendant les appels téléphoniques et les appels dans le navigateur, et OpenAI héberge l'audio. Quand l'appelant a besoin de données de l'entreprise, comme des disponibilités ou une réservation, GPT-Live interroge le worker de Caléonis Receptionist, qui répond avec l'agent réceptionniste. Votre projet OpenAI doit avoir SIP activé et un webhook d'appel entrant pour les appels téléphoniques.
  </Accordion>
</AccordionGroup>

## Connaissances et automatisation

<AccordionGroup>
  <Accordion title="IA compatible OpenAI" icon="sparkles">
    L'agent réceptionniste pour le chat du site Web et les appels utilise par défaut `gpt-6-luna` avec un raisonnement élevé. Pour utiliser un autre fournisseur ou un environnement d'exécution auto-hébergé qui implémente les API de chat et d'embeddings compatibles OpenAI, définissez les variables `AI_CHAT_*` et `AI_EMBEDDING_*`. Le modèle doit prendre en charge les appels d'outils, et les modèles d'embeddings doivent renvoyer exactement 1536 dimensions.
  </Accordion>
  <Accordion title="Firecrawl" icon="globe">
    Firecrawl importe le contenu public des sites Web dans le pipeline de connaissances. Vous pouvez vous en passer si les opérateurs se contentent de importer des documents et de saisir les connaissances à la main.
  </Accordion>
</AccordionGroup>

## Intégrations facultatives

- Google Calendar pour les disponibilités et la synchronisation des réservations
- SMTP pour la vérification, la réinitialisation des mots de passe et les emails opérationnels
- Polar pour la facturation hébergée et l'utilisation mesurée
- PostHog et OpenTelemetry pour l'analytique, le suivi des erreurs, les traces, les métriques et les journaux
- AWS S3 ou un stockage compatible pour les déploiements sur plusieurs hôtes
- MinIO par le profil Compose facultatif `minio`
- PostgreSQL et Redis gérés à la place des conteneurs inclus

Définissez `STORAGE_PROVIDER=s3` pour AWS S3, MinIO ou un autre service compatible. Laissez `S3_ENDPOINT` vide pour AWS S3. MinIO exige son point de terminaison HTTP et `S3_FORCE_PATH_STYLE=true`.

Consultez la [référence des variables d'environnement](/self-hosting/environment-variables) pour les noms de configuration et le [guide Docker Compose](/self-hosting/docker-compose) pour les étapes de déploiement.

## Fournisseurs du pilote et limites

L'instance indépendante doit utiliser ses propres comptes et contrats. La production pilote peut utiliser Resend pour les emails transactionnels ; aucun email réel n'est envoyé par la lecture de ce guide. La facturation Polar demeure conditionnelle à l'approbation du catalogue et au mode test.

Un numéro Voice-only ne fournit pas les SMS. La présence d'un adaptateur de transfert ne qualifie pas le parcours SIP. Vérifiez aussi droits Google, renouvellement, accès privé S3 et restauration des sauvegardes.
