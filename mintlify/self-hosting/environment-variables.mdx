---
title: "Variables d’une instance indépendante"
description: "Identifier les groupes de configuration sans renommer les paramètres internes."
---
`.env.example` et les fichiers de déploiement de la version utilisée font foi. Les variables internes gardent leurs noms LobbyStack ; le rebranding ne doit pas les casser.

## Application et accès

| Variables | Usage |
| --- | --- |
| `APP_BASE_URL` | URL HTTPS de votre instance. |
| `DEPLOYMENT_MODE` | Mode cloud, standard auto-hébergé ou développement selon le code. |
| `DATABASE_URL` | Connexion du rôle principal de chaque service. |
| `LOBBYSTACK_AUTH_PASSWORD`, `LOBBYSTACK_WORKER_PASSWORD`, `LOBBYSTACK_DISPATCHER_PASSWORD` | Accès aux rôles séparés. |
| `LOBBYSTACK_<ROLE>_DATABASE_URL` | Surcharge de connexion d’un rôle si nécessaire. |
| `BETTER_AUTH_SECRET` | Signature de l’authentification. |
| `ENCRYPTION_KEY` | Chiffrement et usages cryptographiques du runtime. |
| `OTP_HASH_SECRET` | Protection des codes de vérification. |

Ne remplacez pas `ENCRYPTION_KEY` à la légère : des identifiants stockés et secrets d’intégration peuvent devenir inutilisables.

## Admin et worker

| Variables | Usage |
| --- | --- |
| `INTERNAL_SERVICE_SECRET` | Signatures internes et jetons courts. |
| `INTERNAL_SERVICE_TOKEN` | Authentification des échanges internes protégés. |
| `WORKER_INTERNAL_URL` | Adresse privée du worker. |
| `REDIS_URL` | Fonctions partagées, dont limites d’accès selon le parcours. |

Vérifiez les valeurs communes nécessaires aux deux services. Ne publiez pas les routes internes.

## Voix

| Variables | Usage |
| --- | --- |
| `LIVE_PROTOTYPE_ENABLED` | Activation du runtime vocal sur les services concernés. |
| `OPENAI_API_KEY` | Accès fournisseur vocal et éventuels replis IA. |
| `OPENAI_WEBHOOK_SECRET` | Vérification du webhook d’appels entrants OpenAI. |
| `TWILIO_SIP_TRUNK_SID` | Trunk configuré pour la chaîne téléphonique. |
| `WEB_CALL_MAX_DURATION_MS` | Limite de durée des appels navigateur. |
| `WEB_CALL_PUBLIC_BUSINESS_SLUG` | Entreprise de démo publique de votre instance. |
| `WEB_CALL_ALLOWED_ORIGINS` | Origines autorisées pour cette démo. |

Une variable configurée ne qualifie pas le transfert humain. Contrôlez aussi la politique effective du fournisseur.

## Fichiers

| Variables | Usage |
| --- | --- |
| `STORAGE_PROVIDER` | Choix local ou S3 selon le déploiement. |
| `LOCAL_STORAGE_PATH` | Répertoire persistant partagé si stockage local. |
| `LOCAL_STORAGE_SIGNING_SECRET` | Signature des accès temporaires locaux. |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION` | Destination du stockage compatible S3. |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE` | Accès et compatibilité du fournisseur. |

Préservez des sauvegardes cohérentes avec la base et testez leur restauration.

## IA, intégrations et observabilité

| Variables | Usage |
| --- | --- |
| `AI_CHAT_*`, `AI_SUMMARY_*`, `AI_EMBEDDING_*` | Modèles, points d’accès et accès IA. |
| `GOOGLE_*` | OAuth et calendrier. |
| `TWILIO_*` | Opérateur et vérification des requêtes. |
| `WIDGET_SESSION_SECRET` | Signature des sessions widget. |
| `WIDGET_KEY_ISSUANCE_ENABLED` | Émission de nouvelles clés, désactivée par défaut. |
| `FIRECRAWL_*` | Import de pages Web. |
| `EMAIL_*`, `SMTP_*` et paramètres Resend du fichier exemple | Email transactionnel selon fournisseur. |
| `PUBLIC_API_RATE_LIMIT_PER_MINUTE` | Limite API configurée. |
| `POLAR_*` | Facturation si configurée et validée pour votre instance. |
| `POSTHOG_*`, `OTEL_EXPORTER_OTLP_*` | Analyse, erreurs et export de télémétrie selon configuration. |

N’utilisez pas des prix ou clés fictifs comme données réelles. Vérifiez la redaction des informations sensibles dans les journaux.

## Secrets

Conservez les secrets côté serveur. Les variables `NEXT_PUBLIC_*` sont destinées aux données publiques et ne doivent contenir aucune clé privée.

L’activation d’un fournisseur peut générer un coût. Gardez les tests sans envoi, achat ou facturation réels tant qu’ils ne sont pas autorisés.
