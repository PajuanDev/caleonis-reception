---
title: "Préparer Docker Compose"
description: "Démarrer une instance de test indépendante puis qualifier chaque intégration."
---
Les commandes suivantes concernent votre installation indépendante. Ne les exécutez pas sur le serveur du SaaS Caléonis.

## Préparer

Utilisez les versions indiquées par `package.json`, le verrou de dépendances et les fichiers Docker du dépôt. Prévoyez PostgreSQL, Redis, un stockage durable et une terminaison HTTPS avant usage public.

Clonez le dépôt auquel vous avez accès :

```bash
git clone https://github.com/PajuanDev/caleonis-reception.git
cd caleonis-reception
node scripts/generate-env.mjs
```

Le générateur prépare les secrets locaux selon le script. Ne passez pas d’option d’écrasement sur une installation existante : changer les clés peut rendre des données ou accès inutilisables.

## Configurer

Lisez `.env.example` et [les variables](/self-hosting/environment-variables). Réglez le domaine de votre instance et ses propres comptes fournisseurs.

Ne mettez pas de valeurs de production Caléonis dans votre fichier. Vérifiez qu’aucun envoi vers un tiers ou achat de numéro ne sera déclenché.

## Démarrer en test

```bash
docker compose --env-file .env up -d --build
docker compose ps
```

Le migrateur applique les migrations avant les services dépendants. Consultez les journaux et les contrôles de santé avant d’ouvrir l’instance.

```bash
curl -fsS http://127.0.0.1:3000/api/health/ready
curl -fsS http://127.0.0.1:3002/health/ready
docker compose logs --since=10m admin worker
```

Ces commandes sont des contrôles locaux ; ne publiez pas les journaux s’ils contiennent des données sensibles.

## Stockage

Le stockage local partagé convient à une topologie mono-hôte. Préservez son volume avec la base.

Sur plusieurs hôtes, configurez un stockage compatible S3 et vérifiez l’accès privé depuis admin et worker. Les profils optionnels MinIO et développement sont décrits par le fichier Compose du dépôt.

## Qualifier avant publication

Vérifiez HTTPS, secrets, ports privés, restauration des sauvegardes, rôles PostgreSQL, accès entre entreprises et files de traitement.

Qualifiez la voix navigateur, puis seulement les appels téléphoniques autorisés avec vos propres comptes. Pour les fournisseurs externes, une opération de test peut avoir un coût.

## Mettre à jour

Sauvegardez base et fichiers au même point de reprise. Lisez les migrations et nouvelles variables, puis testez sur une copie isolée avant le redémarrage de votre instance.

Ne changez pas le code, les migrations ou les sources Railway de la production Caléonis pour installer cette démonstration.
